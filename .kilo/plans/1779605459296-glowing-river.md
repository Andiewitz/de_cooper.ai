# Streak Feature Implementation Plan

## Overview
This plan outlines the implementation of a streak tracking feature for the de_cooper.ai learning platform. The feature will track consecutive days of user activity (lesson creation or messaging) and display this information in the user dashboard.

## Current State Analysis
- Frontend already displays a "Streak" stat showing hardcoded "0 days" in LearnPage.tsx (lines 366-368)
- No backend streak tracking exists
- User model in server/app/models/models.py lacks streak-related fields
- Auth API already has a /me endpoint that returns user data (server/app/api/routes/auth.py line 74-77)
- Lesson creation and chat endpoints exist in server/app/api/routes/lessons.py

## Proposed Changes

### 1. Database Schema Updates
Add streak tracking fields to the User model in server/app/models/models.py:
- `last_activity_date`: DateTime(timezone=True) (nullable) - tracks when user last had activity
- `current_streak`: Integer (default 0) - current consecutive days streak
- `longest_streak`: Integer (default 0) - longest streak achieved

### 2. Backend Logic Updates
Create streak calculation logic and update relevant endpoints:

#### Utility Function
Create a function `update_user_streak(user: User)` in server/app/models/models.py:
- Get current date in UTC (using datetime.now(timezone.utc))
- If user.last_activity_date is None:
  - Set current_streak = 1
  - Set last_activity_date = current date
- Else:
  - Convert last_activity_date to date (strip time)
  - If last_activity_date.date() == current_date.date(): 
    - No change to streak (same day activity)
  - Elif last_activity_date.date() == (current_date - timedelta(days=1)).date():
    - Increment current_streak by 1
    - Set last_activity_date = current date
  - Else:
    - Reset current_streak to 1
    - Set last_activity_date = current date
- Update longest_streak = max(longest_streak, current_streak)
- Return updated user object

#### Endpoint Updates
Update these endpoints to track user activity:
- POST /lessons/ (create_lesson) - when user creates a lesson
- POST /lessons/{lesson_id}/chat (chat) - when user sends a message

In each endpoint, after verifying the lesson belongs to the user:
1. Call update_user_streak(current_user) 
2. Save user changes to database

#### Enhance Existing Endpoint
Extend GET /auth/me in server/app/api/routes/auth.py to include streak data:
- No new endpoint needed - reuse existing /auth/me
- The UserResponse schema already needs updating to include streak fields

### 3. Frontend Updates
Modify client/src/app/learn/page.tsx to display actual streak data:

#### Data Fetching
- Use existing useAuth hook which calls /auth/me
- Update UserResponse type in auth-provider to include streak fields
- Access streak data through user object from useAuth()

#### Display Update
Replace hardcoded values in lines 366-368:
- Line 366: {user?.current_streak ?? 0} days instead of "0 days"
- Line 367: Keep "active streak" label or enhance to show longest streak on hover/tooltip

### 4. Implementation Details

#### Activity Definition
For streak purposes, consider these activities:
- Creating a new lesson (POST /lessons/)
- Sending a message in a lesson (POST /lessons/{lesson_id}/chat)

#### Timezone Handling
- Use timezone-aware datetime comparisons throughout
- Compare dates only (strip time) for streak calculation
- Use UTC consistently (server time)

#### Edge Cases Handled
- First activity: sets streak to 1
- Same-day multiple activities: no change to streak (maintains current value)
- Missed day: streak resets to 1 on next activity
- Multiple days missed: streak resets to 1 on next activity
